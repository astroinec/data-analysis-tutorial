3-1缺失值与重复值

不急着删行，先说明一行代表什么，再处理重复、缺失与修复记录。

  • 约 60 分钟
  • 难度 ★★☆
  • 配套练习本 notebooks/3-1_clean_missing.ipynb
  • 前置：已完成阶段 2，能读取 CSV、筛选和关联表格

本课要交付什么

本课目标

  • 用 isna() 和 duplicated() 给一份表做体检。
  • 区分“整行重复”和“同一个订单编号出现多次”。
  • 依据字段含义处理缺失，保留原表与处理记录。
  • 解释为什么未评分不应填成 0。

打开 3-1 练习本，选择 Python (da-course)。在原来的 notebooks 文件夹运行，不要单独把练习本拖到桌面。数据是随包提供的虚构订单，不是实际商家的经营记录。网页帮助你理解决策，Notebook 才真正运行 Python。

1. 清洗不是把表洗成“没有空格”

想象整理一份访谈记录：受访者没有回答，不等于回答了“不同意”；同一段记录被复制两次，也不等于发生了两次访谈。数据清洗同样要尊重信息原意。

NaN、pd.NA 等是 pandas 表示缺失的方式。不要写 值 == NaN 判断缺失，用 isna()；它返回每个位置是不是缺失的布尔值。sum() 把 True 当作 1 相加，就得到缺失数量。notna() 则反过来选择已有内容的位置。空字符串、只有空格的文本不一定自动成为缺失，需要另行核对。

不分原因地消灭缺失

raw.dropna() 会删除任何一列为空的订单。顾客没评分，也会让其实际支付金额从销售统计中消失。

把问题按字段拆开

数量缺失会影响销量；评分缺失只说明没观察到评分；品类可能通过商品主表补全。三者不是同一种处理。

2. 先拍“处理前照片”

下面的 Python 放在 Notebook 代码格，而不是 Anaconda Prompt。

import pandas as pd
raw = pd.read_csv("../data/shop/orders_dirty.csv")
print("行列数：", raw.shape)
print("整行额外重复：", raw.duplicated().sum())
print(raw.isna().sum())

本版文件有 2060 行、11 列，包含 60 行额外的整行重复。这不是要背的标准答案，重新拿到文件时应重新运行体检。缺失和重复可能重叠，所以不要将每列的缺失数相加当成“需要删除的行数”。同一行可能同时没有数量和品类。

观察层级 本版结果或检查方式 能说明什么
原表行数 2060 导出文件的记录数，尚非去重订单数
整行额外重复 60 每组第一次以外的完全相同行
去重后行数 2000 本模拟数据抽取的订单数
去重后的数量缺失 unique["数量"].isna().sum()，本版 35 需要核对的订单，不应猜成 1
评分缺失 动态计算 无观察值，不等于评分为 0

“第一次以外”很重要：一条记录出现两次，duplicated() 默认标记后一条，所以结果是 1；duplicated(keep=False) 会标记两条，适合把问题组全部找出来，结果是 2。

3. 判断一行的粒度，再决定去重

本模拟数据规定：一行代表一个订单、一个商品，订单编号唯一。实际系统可能一个订单包含多条商品明细，那时仅按订单编号去重就会吞掉正常商品，必须改用“订单编号 + 明细编号”等键。粒度是数据的身份证规则，不能只凭列名猜。

duplicate_log = raw.loc[raw.duplicated()].copy()
unique = raw.drop_duplicates().copy()
print(unique["订单编号"].duplicated().sum())

drop_duplicates() 不指定 subset 时按全部列比较。本课保留第一次并记录被移出的整行。本版去重后的订单编号不再重复。如果仍重复，要检查同一编号是否有状态更新、字段冲突或合法明细；不要直接 drop_duplicates("订单编号") 当作万能修复。

重复与缺失：先观察再处理

组件仅演示小表，不会读取你的文件，也不会执行 Python。先试“按整行去重”，再看为什么“不评价”不该影响订单金额。

4. 缺失的三个处理方向

保留，并说明分母

平均评分只计算有评分的订单，同时报告已评分数量和覆盖率。pandas 的 mean() 默认跳过缺失，不会自动把它们视为 0。

根据可信主表补回

缺失品类可用原订单表的商品 ID 关联商品主表。补回前确认关联键唯一，避免一笔订单变成两行。

标记或隔离待核对

数量缺失先保留在审计表。做需要数量的分析时标记为待核对，不能悄悄填平均数、填 1 或删除所有空值。

本包包含可信的模拟原订单和商品主表，因此可以演示有依据的修复：

orders = pd.read_csv("../data/shop/orders.csv")
products = pd.read_csv("../data/shop/products.csv")
master = orders[["order_id", "product_id"]].merge(
    products[["product_id", "category"]],
    on="product_id", how="left", validate="many_to_one"
)
category_lookup = master.set_index("order_id")["category"]
recovered = unique["订单编号"].map(category_lookup)
clean = unique.copy()
clean["品类"] = clean["品类"].fillna(recovered).fillna("未知")

map() 按订单编号寻找可靠品类，fillna(recovered) 只补缺失的位置，不会覆盖已有品类。最后的“未知”是公开承认仍无法恢复，而不是随便归到“文具”。没有原订单主表时，可以直接标记未知并向数据负责人求证；不能假装有可靠答案。现实中主表也可能过期，应检查版本、有效日期及关联覆盖率。

5. 留下别人能复核的记录

repair_log = clean.loc[unique["品类"].isna(),
                       ["订单编号", "品类"]].copy()
repair_log["原因"] = "原品类缺失；按原订单商品ID关联主表"
quantity_review = clean.loc[clean["数量"].isna()].copy()
ratings = clean["评分"]
print("观察到的评分数量：", ratings.notna().sum())
print("有评分订单的平均分：", ratings.mean())

这里暂时仍有越界评分，下一课会识别；这不是最终满意度结论。“没有缺失”也不代表数据正确，6 分出现在五分制字段就是另一个问题。记录至少写明订单编号、旧值、新值、理由与规则版本。保存时另起文件名，不覆盖 orders_dirty.csv；导出方法会在后续项目中用到。

6. 动手练习与提示

练习 1：体检记录

分别计算原表行数、额外整行重复数、去重后数量缺失数。为什么不能直接把原表的数量缺失数当作需要核对的独立订单数？

提示与答案

使用 raw.shape[0]、raw.duplicated().sum()、raw.drop_duplicates()["数量"].isna().sum()。本版为 2060、60、35。原表中的同一缺失订单可能被重复导出。

练习 2：保留去重后的订单

创建新表，不修改 raw，并确认整行重复数与订单编号重复数。

参考答案

dedup_answer = raw.drop_duplicates().copy()。两种重复数量本版都为 0；若键重复但行不完全相同，应先查看差异而不是继续删。

练习 3：按可信来源补品类

用已建立的 category_lookup 补缺失品类，无法关联时标记“未知”。说出为什么不用最常见品类填补。

参考答案

unique["品类"].fillna(unique["订单编号"].map(category_lookup)).fillna("未知")。众数填补会人为增加热门品类订单，扭曲品类结构。

练习 4：报告评分分母

在下一课之前，仅观察“原表去重后已有评分”的平均值和数量，同时注明尚未处理越界评分。

参考答案

unique["评分"].mean() 与 unique["评分"].notna().sum()。不要用 fillna(0).mean()，也不要声称此时的平均分已符合五分制质量要求。

一笔已完成订单没有评分，分析实付金额时最合理的是？

是否能用于分析，要按分析所需字段判断。评分缺失并不抹掉一笔支付记录。

7. 报错、求职用途与验收

遇到的问题 先做什么
KeyError: '数量' print(raw.columns.tolist())，确认读取的是中文字段脏表
MergeError 查主表键是否重复，不要取消 validate 来绕过问题
去重后行数不对 检查是否用了 dropna() 或只按订单编号去重
一次运行得对、重启后出错 从本练习本第一格按顺序运行，不依赖上一课变量

求职加分

面试可以说明：“我先确认订单粒度，再分别记录整行重复、关键字段缺失和可关联修复项；评分只对有效观察计算，并交代分母。”这是方法展示，不是虚构“为企业提升营收”。保留审计记录比仅展示清洗后行数更有说服力。
