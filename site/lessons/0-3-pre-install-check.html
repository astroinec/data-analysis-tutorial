阶段 0 · 出发准备

0-3安装前体检：识别已有 Python、检查路径和磁盘

盘点系统和已有 Python，不破坏旧工具，为独立课程环境选一个可写的位置。

  • 约 30 分钟
  • 难度 ★☆☆
  • 前置：已读电脑基础；知道如何复制实际路径与显示扩展名。

本课目标

  • 确认 Windows、系统架构、磁盘空余与课程目录权限。
  • 理解多个 Python 可以共存，安装前不强制卸载。
  • 能解释 where python 和 WindowsApps 别名为什么不能单独证明解释器正常。
  • 写下一张安装记录卡，并识别需要先停止、求助的情况。

1. “清理”应当理解为盘点，不是删除

如果目录页仍使用“清理旧 Python”的历史标题，请以这里的做法为准：先盘点，默认保留已有工具与环境。以前为工作、学校或其他软件装过 Python，并不妨碍本课程使用 Anaconda 的独立 da-course 环境。盲目卸载可能让其他项目不能运行；删除 PATH、envs 或用户文件夹不是新手安装的前置步骤。

这些操作本教程不要求

不重命名 C:\Users\... 的 Windows 用户配置目录，不删除不认识的 Python/conda 环境，不编辑整个系统 PATH，不清除注册表，不关闭杀毒，不为了方便长期以管理员启动终端。工作或学校管理的电脑不能自行绕开管理策略。

2. 先确认电脑属于哪条路线

按 Win+I 打开“设置”，进入“系统 → 系统信息/关于”。记录“Windows 规格”与“系统类型”。本教程面向 Windows 11、64 位、x64 处理器（x86_64）。安装器网页可能提供多种系统版本，不要把 macOS、Linux 或 ARM 的包当作同一包。

设置中的系统信息（界面示意，不是实机截图）
位置 观察示例 判断
Windows 规格 Windows 11 目标系统路线
系统类型 64 位操作系统，基于 x64 的处理器 使用官方 Windows x86_64 安装器
其他可能显示 基于 ARM 的处理器 不把 x64 教程冒称 ARM 原生验证，先确认官方支持与单位要求
旧系统或 32 位 Windows 10 / 32 位系统 不照搬本课宣称完全兼容；需另行核对系统与安装器条件

本教程制作与自动检查不代表作者已在你的 Windows 机器上实测。如果你是 macOS/Linux 用户，可以阅读概念，但 Prompt、cd /d 与安装界面不适用；不要照抄 Windows 命令。对于 ARM 或受管理电脑，先保存系统信息并向设备支持人员确认，不继续试一串不同安装器。

磁盘与权限

按 Win+E，左侧选“此电脑”，看预备安装盘的“可用空间”。Anaconda、独立环境、包下载缓存都需要空间；建议先预留约 15～20 GB 作为学习操作余量，这不是官方固定最低要求，实际占用随安装器与依赖变动。空间明显不足时先按自己的资料备份与系统存储管理流程处理，不删除未知目录。

在准备放教程的普通文件夹中右键 → 新建 → 文本文档，输入“路径测试”，保存，再打开读一遍。新建自己的测试文件是检查写权限；读完可自行保留，不涉及删除其他文件。如果无法保存，不要把整课改为管理员运行；换到有权限的目录或询问设备管理员。

3. 中文用户名、空格与安装位置

中文用户名不是必然出错，也无需把 Windows 账户目录改名。Python 本身可以处理 Unicode 路径；部分第三方工具可能在特殊路径中有兼容性问题，必须根据具体错误判断。路径中的空格在命令行用双引号包住，不等于必须删除空格。

Anaconda 官方建议安装目录避免空格和特殊字符，用于减少开源工具兼容问题。与其修改现有用户配置，不如选一个自己有权限、简短的安装位置，例如 D:\Anaconda3；如果只有 C 盘，可考虑有权限的 C:\Anaconda3。这些是路径示例，不保证每台机器可写。标准用户无法写入时，应选择实际可写的简短目录，或询问支持人员怎样提供合规可写目录，不自行扩大系统目录权限。

安装 Anaconda 的位置与解压教程的位置是两个不同文件夹。不要把教材放在 Anaconda 安装目录或环境的 site-packages 里面；教程文件需要你以后能找到、保存和备份。

项目 示例 是否必须一样
Anaconda 安装目录 D:\Anaconda3 不同，记录实际位置
教程根目录 D:\da-course\data-analysis-tutorial 不同，命令换成实际位置
Windows 用户目录 C:\Users\你的账户名 不改名、不删除
conda 环境名称 da-course 本课程保持此名字

4. 查已有 Python：看见多个不是坏事

本节仅盘点，可以用 Windows 搜索打开 命令提示符（CMD），正常权限运行；这一节特意用普通 CMD 是为了观察已有系统命令。安装后课程操作统一换成 Anaconda Prompt，不要把两种窗口混用。

在普通 CMD 输入：

where python
where conda

输出会列出当前这个窗口可搜索到的路径，可能有多个；也可能显示“信息: 用提供的模式无法找到文件”。where 不会删除、安装或修复任何东西。普通 CMD 找不到 conda，不代表 Anaconda 没装：本课程不要求把 conda 永久加进系统 PATH。

C:\Users\某用户\AppData\Local\Microsoft\WindowsApps\python.exe
C:\...\Python312\python.exe

这是路径示例，不是你必须得到的顺序。WindowsApps 中的 python.exe 可能是“应用执行别名”，是一个把 python 命令转到应用/商店的入口，不一定是可运行课程的真实 Python。若输入 python --version 弹出应用商店，先关闭商店，记录当前用的是普通 CMD；之后在 Anaconda Prompt 激活课程环境再验证。

Windows 11 可在“设置 → 应用 → 高级应用设置 → 应用执行别名”查看 Python 相关入口；界面名称可能变动。不用为了本课程先关所有别名。只有确有命令被别名抢占、又需要在普通终端使用时，了解影响后再决定相关 Python 项；不要禁用无关应用，也不要删除 WindowsApps。

三个问题，三个证据

要回答的问题 后续如何查看 不足以证明的东西
这个窗口能搜索到哪些 python？ where python 不能证明 Notebook 内核用哪一个
实际执行的是哪个 Python？ python -c "import sys; print(sys.executable)" 窗口名字不等于实际路径
Notebook 正在用哪个 Python？ 代码格运行 import sys; print(sys.executable) Prompt 中版本正确不等于内核也正确

以后始终用 python -m pip，意思是“请当前这个 Python 执行自己的 pip 模块”。裸 pip 可能指向另一个安装；pip 与 python 都叫命令，不意味着它们天然绑定。当前不用安装任何课程包，等创建 da-course 后再安装。

已经装过 Anaconda 怎么办

从开始菜单打开 Anaconda Prompt，输入 conda --version 与 conda info --envs 盘点。看到现有环境先保留；如果 da-course 已存在，先检查版本与归属，不重新创建覆盖。基础安装损坏或命令不运行时去故障排查，不要直接卸载连带删除环境。

5. 网络、下载与许可：提前知道停止条件

环境创建与依赖安装需要联网；网页讲义、已装好的 Python 练习和体检脚本可以离线使用。公司代理、认证网络、证书审查会影响下载。若后续出现代理、证书或服务条款提示，先保存完整信息，按真实用途阅读官方条款与单位要求，不照抄教程替你接受协议。

不用不明安装器、所谓“一键修复包”或聊天附件中的证书。不要通过关闭 SSL 校验、修改为 HTTP、添加随意 trusted-host 绕过证书错误。不把代理用户名与密码发给别人。

安装记录也是排错证据

求职作品需要别人能重现你的环境。记录系统类型、安装位置、环境名与版本，不必在简历写一串安装细节，但在项目说明中可以用它解释“怎样复现”。

参考记录

“Windows 11/x64；安装盘空余约……GB；教程在……；文本保存成功；普通 CMD 的 where python 出现 WindowsApps；已有 Anaconda 情况待核对。”填自己的实际观察，不复制示例当结果。

中文不是必然故障。重命名用户配置目录可能破坏账户与软件引用，不能作为入门操作。

练习 3：多个 Python 的意义

普通 CMD 的 where python 出现两个路径，你能断言 Notebook 用了第二个吗？提示：Notebook 有自己的内核。

参考答案

不能。where 只反映当前终端的搜索结果，Notebook 要运行 sys.executable 查看自己的解释器。不要因两个路径就卸载其中一个。

练习 4：何时停止

磁盘不足、单位电脑无权限、安装下载出现证书错误，分别应该先做什么？

参考答案

磁盘不足先备份自己的文件并用正规存储管理流程评估；无权限先换有权限的位置或问设备管理员；证书错误保留报错并确认代理/时间/单位 CA 要求。三者都不靠管理员常驻、关杀毒或关闭 SSL 来解决。
