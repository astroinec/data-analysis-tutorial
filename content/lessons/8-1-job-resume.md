## 1. 文科生求职数据分析，面试官真正在看什么？

初级数据分析岗（商业分析、运营分析、产品分析、电商数据专员）通常并不要求你手写底层算法，而是看四项硬核基本功：

:::cards 招聘方最看重的四件事
:::card 1. 取数与清洗基本功
SQL（连接、聚合、CASE WHEN、窗口函数）+ Python/pandas（筛选、透视、清洗、画图）+ Excel。不需要“精通十种工具”，关键是**手写不卡壳、对账不出错**。
:::
:::card 2. 指标口径与拆解思维
接到模糊问题，能不能拆成清晰公式？有没有把退款算进收入？有没有把未评分填成 0？有没有把观察窗口截断？
:::
:::card 3. 统计直觉与证据边界
知道平均数会骗人、相关不等于因果、A/B 测试要看 SRM 和护栏指标，敢于说清“现有数据暂时不能证明什么”。
:::
:::card 4. 业务表达与汇报能力
**这是文科生的主场优势**：能不能把枯燥数字写成人话，用“结论先行 + 图表佐证 + 下一步验证方案”让业务方一眼看懂。
:::
:::

## 2. 简历怎么写项目经历？绝不虚构真实业绩！

:::warn 求职诚信红线
本教程的文创店、墨读 App、A/B 实验均为虚构教学数据。在简历中**必须诚实标注为“个人分析项目 / 模拟数据集项目”**，**严禁**编造“在某公司实习期间推动 GMV 增长 20%”或把模拟结论包装成真实上线收益。面试官追问埋点表名、上线排期和跨部门阻力时，虚构经历会被瞬间识破。
:::

:::compare 同一份项目的简历写法对照
:::bad 空洞堆砌或过度夸大
- 熟练掌握 Python、SQL、统计分析、A/B 测试。
- 负责线上文创店年度销售数据分析，发现双十一大促效果极佳，成功帮助店铺全年营收突破 178 万。
:::
:::good 诚实、具体、有方法与证据（个人项目）
**个人分析项目｜线上文创店年度销售与 RFM 分层分析（模拟数据集，15,115 笔订单）**
- **口径与质量核验**：独立界定已完成净销售额、订单退款率与窗口复购率口径，使用 `left merge + many_to_one` 校验多表关联无增行、无丢单，隔离未评价缺失值避免误删 6,969 笔订单。
- **分析与拆解**：通过“人数 × 频次 × 客单价”乘法拆解，定位 12 月销售额环比 −11.4% 的主因是购买人数与频次下降（而非客单价下跌）；基于中位数阈值构建 RFM 八类分层，识别出 31.2% 的重要价值客户贡献了 69.9% 的已完成销售额。
- **交付**：产出可复现 Jupyter Notebook、SQL 取数脚本及结构化分析报告（含数据局限与待验证建议）。
:::
:::

## 3. 打造让人眼前一亮的作品集（Portfolio）

一份能让面试官点开看 2 分钟的作品集，胜过简历上写十句“熟悉 Python”。建议包含 2～3 个互补项目（例如：电商综合分析 P-1 + 漏斗留存 P-2 + A/B 测试 P-3），每个项目结构如下：

:::steps 作品集目录标准结构
:::step 1. 一页执行摘要（README / PDF 首页）
用 300 字讲清：分析背景、数据规模（注明模拟/公开来源）、核心指标卡、3 条核心发现与 2 张最关键的图。让 HR 和业务主管 30 秒内看懂你的水平。
:::
:::step 2. 完整分析报告（Markdown 转 PDF）
按 `report/analysis-report-template.md` 撰写，包含指标口径表、数据体检记录、图表解读、局限说明与下一步验证设计。
:::
:::step 3. 可复现代码（Notebook + SQL）
重启内核从头到尾一键运行无报错；图表中文显示正常、标题标明时间与单位；写明运行环境与数据来源声明（注意公开数据的许可边界，见 [数据集说明](lesson:A-3)）。
:::
:::

:::try 练习 8-1.1 改写 P-2 项目简历要点
把“我分析了墨读 App 6000 个用户的漏斗和留存，画了热力图，发现信息流广告不好”改写成一条 2～3 行的专业简历要点。
:::fold 参考答案
**个人分析项目｜墨读 App 新用户转化漏斗与留存分析（模拟数据集，6,000 名用户）**
- 构建五步去重转化漏斗与 D1/D7/D14/D30 同期群留存表，核验 30 天完整观察窗口避免右截断偏差。
- 分渠道与分设备下钻定位两大瓶颈：信息流广告渠道“试听→点击付费”转化（26.4%）与 D7 留存（12.1%）显著偏低；Android 端“点击付费→支付成功”转化率（50.6%）比 iOS（59.9%）低 9.3 个百分点。
- 提出渠道投放复核与 Android 支付链路排查两项待验证假设，交付可复现分析本与报告。
:::
:::

:::try 练习 8-1.2 改写 P-3 项目简历要点
用 3 行写出项目三（A/B 测试）的简历要点，必须同时体现 SRM、护栏指标和人群异质性。
:::fold 参考答案
**个人分析项目｜商品详情页新版评价卡片 A/B 测试复盘（模拟数据集，12,000 名用户）**
- 完成 50/50 分流 SRM 校验（p=0.66），通过卡方检验确认总体转化率显著提升 +1.31pp（p=0.014），同时用 Welch t 检验发现护栏指标页面加载耗时增加 +43.5ms（p<0.001）。
- 分新老客下钻发现增益几乎全部来自新客（+2.49pp，p=0.0003），老客无显著变化（p=0.82），据此提出“优先面向新客灰度或先优化前端性能再全量”的分层上线建议。
:::
:::

:::try 练习 8-1.3 作品集公开合规检查
如果你打算把自己的分析项目上传到 GitHub 作为作品集，关于数据文件应该注意哪两点？
:::fold 参考答案
1. 明确标注模拟数据或公开历史数据来源，不冒充真实企业机密数据，也绝不上传真实公司导出的脱敏不彻底的用户隐私表。
2. 公开数据再发布前核实许可证（如 `tips`/`titanic` 未确认再发布条款时，仓库可只放代码、汇总图与报告，数据由读者按来源说明自行获取）。
:::
:::
